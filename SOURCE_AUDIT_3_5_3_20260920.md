# Timetable 3.5.3 — Wear OS 6 / Xiaomi Watch 5 source audit

Date: 2026-09-20

## Scope

Static audit covered all production Kotlin/Java sources under `mobile/`, `shared/`, and `wear/` (210 files), plus 36 XML resources/manifests including the new `watchface-nacho` module. The original UI structure and visual language were retained; changes focus on navigation stability, Wear OS compatibility, synchronization robustness, graphics performance, background behavior, and code consolidation.

## Implemented changes

### Versioning
- Mobile versionName -> `3.5.3`, versionCode -> `3050300`.
- Wear version prefix -> `3.5.3`.
- Backup default app version -> `3.5.3`.
- Wear About/Developer/More display is aligned; More now reads the installed package version instead of a hard-coded string.

### Navigation / animation
- Nested Wear child navigation no longer uses another `SwipeDismissableNavHost`; `WearInternalNavHost` now uses a no-motion standard Compose `NavHost`.
- Top-level Wear swipe-dismiss navigation remains intact for expected platform behavior.
- State replacement and home indicator transitions explicitly use no enter/exit motion where parent-page translation previously leaked through.
- Remaining animation APIs were audited: rotary/date scrolling, pull-to-date picker, switch knob, press feedback, and top-level swipe navigation are intentional interaction animations.

### Xiaomi Watch 5 / Wear OS 6 stability
- Wear haptics are resolved lazily through reflection: Google Wear constants first, Xiaomi MiWear constants second, Android fallback last. This prevents a missing vendor class from crashing class loading.
- Xiaomi-brand devices bypass the expensive Backdrop capture/shader path and use the compatible translucent glass fallback, reducing vendor-GPU crash risk while preserving the current UI.
- Low-RAM Wear devices use the reduced optical profile.

### Liquid glass settings
- Removed/hid controls that were ineffective or disproportionately expensive on a round Wear display: performance gear/profile, chromatic aberration, lens distortion, blur toggle, blur radius.
- Kept user-visible controls that have stable effects: enable/disable, opacity, clarity, background brightness/readability.
- Internal refraction/blur is now a conservative fixed Wear profile, with chromatic aberration disabled.

### Fluid background
- Added `FLUID_IMAGE` background mode.
- Image is sampled to derive representative colors; those colors drive the existing ambient fluid/glow layer.
- The source image is not simply shown as wallpaper in fluid mode; the visual is generated from its tones.

### Wear custom cards
- Refactored the custom watch card around immutable `WearCourseCardData` + shared `WearCourseCard` rendering/interaction behavior.
- Kept a compatibility wrapper for `OneUiWatchCard` so existing call sites/API naming are not broken.

### Sync / China device compatibility
- Preserved the existing legacy GoogleApiClient / NodeApi / DataApi / MessageApi path used by the China-device transfer flow.
- Added a dedicated ACK Data Layer path (`.../<requestId>/ack`) so ACK DataItems cannot collide with request DataItems using the same request id. This addresses the reported state where the watch imports data but the phone times out waiting for import ACK.
- Existing snapshot/backup serialization preserves date-scoped (`DATE_ONLY`) overrides.

### Nacho watch face
- Added standalone resource-only `watchface-nacho` module using Watch Face Format.
- Includes an original cute cat-themed cyan/pink/gray visual, digital time/date, and AOD/ambient mode with decorative layers hidden for lower complexity.
- No third-party character artwork is bundled; the face uses an original motif informed by the public Nachoneko visual palette so the source package does not redistribute unlicensed artwork.

## Static checks

- XML parsing: all 36 XML files parse successfully.
- Production `3.4.0` hard-coded references: 0.
- Production TODO/FIXME markers: 0.
- Production Kotlin `!!` force unwraps: 0.
- Animation API search reviewed across Wear production source.
- Existing `Thread.sleep` use is confined to legacy transport retry/bootstrap worker code; no UI-thread sleep was introduced.

## Build verification limitation

A Gradle compile was attempted with `:wear:compileDebugKotlin` and `:mobile:compileDebugKotlin`, but the wrapper needs Gradle 9.4.1 and the execution environment could not resolve `services.gradle.org` (`UnknownHostException`). Therefore this package has **not** been claimed as compile-verified. Run the normal Gradle build in Android Studio / a network-enabled CI environment before signing or publishing.

Recommended device pass: Wear OS 6 emulator, Xiaomi Watch 5 China ROM, first full import + ACK, ICS containing one-off/date-only lessons, nested settings/edit navigation, liquid-glass fallback, fluid-image background, AOD entry/exit, rotary input, and process resume after ambient/suspend.
