# Build 10.2 Hotfix — 2026-09-09

## Fixed

1. Wear release compilation
   - `TimetablePager.kt` read `minuteTick` outside its lexical scope.
   - The periodic 30-second status tick now lives in the non-empty course branch where the course item lambda can observe it.

2. Wear → phone export delivery
   - Wear export previously wrote the legacy base Data Layer path `/timetable/file-transfer/v1`.
   - Phone receiver only accepted request-scoped child paths, so the production export was filtered out even though probe Message/DataItem tests passed.
   - New exports now use `/timetable/file-transfer/v1/<requestId>`.
   - Receivers accept both the legacy base path and request-scoped paths for compatibility.

3. Phone app display after Wear export
   - The selected export file is still saved to `Downloads/Timetable`.
   - A canonical JSON backup asset is transferred alongside ICS/CSV/JSON and imported into the phone database with replace-matching semantics.
   - This allows the mobile timetable list to update while preserving exact timetable metadata.

4. Incremental-sync ACK routing
   - Wear ACK now uses a request-scoped Data Layer path so the phone listener can receive it.

5. Phone → Wear import result UI
   - Import screen now listens to the action emitted by the actually registered `WearOsSyncReceiverService` instead of the obsolete transfer-service action.

## Validation

- `WearFileTransferProtocol.kt` compiles with the available Kotlin compiler.
- Modified source files were checked for balanced braces/parentheses and stale path usages.
- Full Gradle compilation could not be executed in this environment because Gradle 9.4.1 is not cached and the environment cannot reach `services.gradle.org`.
